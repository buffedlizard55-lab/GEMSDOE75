Executive summary: exactly how to make a submission

This page exists to answer one question precisely: what do I click, and what do I type, to submit a prediction file to the DOE GEMS Prize on DrivenData. It also explains, mechanically, why the error "Predicted values must be in range [0, 1]" happens and how this project's code prevents it.

Step 0 — one-time account setup

  1. Create or log into a DrivenData account: drivendata.org/accounts/login.
  2. Register for the competition at drivendata.org/competitions/306/competition-doe-gems. Eligibility is restricted — see the Official Rules PDF, section 1.3, for who may compete and win a cash prize.

Step 1 — get the data (requires your login; this project cannot do this for you)

Open the data download page and download:

  • training_features.tif — the 17-category GeoDAWN feature stack
  • labels.tif — the USGS/INGENIOUS fault catalogue raster
  • sample_submission.tif — a correctly-formatted all-absent template; this is the single most important file to copy the geometry from
  • 1m_DEM_links.csv — links to the 1 m lidar DEM tiles, if your approach needs them

Place them in this repository's data/raw/ folder with exactly those names.

Step 2 — build your prediction raster

Whatever model or rule you use, it must produce a single 2-D array matching sample_submission.tif in shape, CRS (EPSG:32611), resolution (100 m) and affine transform, with values meant to represent fault probability.

Step 3 — write and validate the file (this is what fixes the [0, 1] error)

from gems_doe.submission_io import SubmissionTemplate, write_submission

template = SubmissionTemplate.from_raster("data/raw/sample_submission.tif")
report = write_submission(your_array, "my_submission.tif", template)
print(report.to_json())
assert report.ok

write_submission always: (1) strips the known float32 nodata sentinel (-3.4028234663852886e38, used inside training_features.tif itself and copied forward by careless code), (2) clips every remaining value into [0, 1], (3) writes no nodata tag by default so there is no ambiguity for the validator to mis-read, and (4) re-opens the file it just wrote and re-checks it — never trusting the in-memory array. Or validate any file you already have:

python scripts/verify_submission.py my_submission.tif --template data/raw/sample_submission.tif

Step 4 — the submission form itself

On the competition's "New submission" page:

  1. File to submit — click "Choose file" and select your validated .tif (or a .zip containing exactly one GeoTIFF).
  2. Note (optional) — a short, specific comment so you can tell submissions apart later. Convention used throughout this project family: <short-id>-<mechanism>-<date>: <one-line result>, for example h75-2-seismic-anisotropy-20261101: holdout DTI 0.xx [95% CI ...], n=... withheld faults. Always label every number HOLDOUT-DTI or ORGANIZER-CONFIRMED — never write a projection as a score.
  3. Click submit. You have a limited number of scored submissions per week — see the rules PDF and the competition page for the current cap. Only spend one on a hypothesis that has already beaten your own best spatially-blocked holdout score.
  4. Remember: you select one single submission before the deadline — it is used for both Phase 1 (private pre-registered new-fault set) and Phase 2 (expert-expanded label set) scoring.

Common rejection: "Predicted values must be in range [0, 1]"

MechanismCauseFix in this project
Sentinel leaktraining_features.tif uses -3.4028234663852886e38 as a nodata flag (see the reference solution's own loader: X_orig[X_orig < -1e38] = np.nan); if that value is copied into your output band unchanged, it is far outside [0, 1]. sanitize_prediction() strips it before writing.
Untagged NaNWriting NaN outside the footprint is legal per the organizer's spec ("null or nan"), but a stray NaN with no declared nodata tag can be read by a strict validator as out-of-range. write_submission() defaults to writing 0.0 (not NaN) outside any footprint mask, and only writes a nodata tag when you explicitly request the NaN-outside form.

What this project cannot do for you right now

It cannot download training_features.tif/labels.tif itself (login-walled; see Limitations). Steps 0-1 above are the only manual, human steps left in the entire pipeline — everything from Step 2 onward is code, already written and tested in this repository.
