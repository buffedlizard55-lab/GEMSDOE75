2.1 Exact Mathematical Anatomy of the Competition Metric (DW-Tversky)

From the official DrivenData reference repository (drivendataorg/gems-prize-reference-solution) and pinned vendor/gems57/metric.py, submissions are scored on the Distance-Weighted Tversky Index (DTI) with false-positive weight $\alpha = 0.2$, false-negative weight $\beta = 0.8$, and a 2-D isotropic triangular spatial-tolerance kernel of radius $R = 300\text{ m} = 3.0\text{ px}$ ($100\text{ m}$ grid):

$$k(d) = \max!\left(0,\; 1 - \frac{d}{R}\right), \qquad d = |x - y|_2, \quad R = 3.0\text{ px}.$$

For a predicted probability field $P \in [0, 1]^{\Omega}$ and hidden test ground-truth binary fault mask $G \in {0, 1}^{\Omega}$ on the valid study footprint $\Omega$ ($|\Omega| = 5,167,373\text{ px}$, $\approx 51,674\text{ km}^2$ in EPSG:32611), let the distance-buffered envelopes be:

$$\widetilde{G}(x) = \max_{g \in G} k(|x - g|2), \qquad \widetilde{P}(g) = \max{x \in \Omega} \big[\, P(x)\, k(|g - x|_2) \,\big].$$

Then the weighted true-positive, false-positive, and false-negative masses are:

$$\text{TP}w = \sum{g \in G} \widetilde{P}(g), \qquad \text{FP}w = \sum{x \in \Omega} P(x)\,\big(1 - \widetilde{G}(x)\big), \qquad \text{FN}w = \sum{g \in G} \big(1 - \widetilde{P}(g)\big) = |G| - \text{TP}_w,$$

and the competition score is:

$$\text{DTI}(P, G) = \frac{\text{TP}_w}{\text{TP}_w + 0.2\,\text{FP}_w + 0.8\,\text{FN}_w} = \frac{\text{TP}_w}{0.8\,|G| + 0.2\,\text{TP}_w + 0.2\,\text{FP}_w}.$$

Look closely at the denominator $0.8\,|G| + 0.2\,\text{TP}_w + 0.2\,\text{FP}_w$:

  1. The $\max$-envelope operator $\widetilde{P}(g)$ is submodular and non-additive over $3.0\text{ px}$ balls: Once a single emitted dot $x_0$ with $P(x_0) = 1$ sits within distance $d \le 1.42\text{ px}$ of a ground-truth fault pixel $g$, that single dot already delivers $\widetilde{P}(g) = 1 - d/3 \ge 0.527$ across a 29-pixel Euclidean disk ($\pi R^2 \approx 28.3\text{ px}$). Adding 10 more contiguous pixels along the same 300 m rib segment increases $\text{TP}_w$ only marginally while multiplying the false-positive penalty $0.2\,\text{FP}_w$ by 11x everywhere the rib misses $G$.
  2. Marginal admission threshold: Differentiating $\text{DTI}$ with respect to a new dot of mass $1$ shows that adding a dot improves $\text{DTI}$ if and only if its marginal expected true-positive kernel gain $\Delta \text{TP}_w$ satisfies: $$\frac{\Delta \text{TP}_w}{\Delta \text{FP}_w} > \frac{0.2\,\text{DTI}}{1 - 0.8\,\text{DTI}} \approx 0.0714 \quad (\text{at }\text{DTI} = 0.2778).$$

5.1 Why Earlier Submissions Triggered "Predicted values must be in range [0, 1]"

Our line-by-line audit of training_features.tif, sample_submission.tif, and upstream submission scripts identified two exact technical mechanisms that trigger the DrivenData portal error "Predicted values must be in range [0, 1]":

  1. Mechanism A — Unflagged -3.4028235e+38 (-FLT_MAX) Sentinel Leakage Inside the Active Footprint (IR-75-SENTINEL-NODATA): In training_features.tif, the GeoTIFF header sets nodata = None, yet 58,171 band-pixel values across 3,073 active-footprint pixels (3,061 boundary pixels across 18 bands + 12 additional interior pixels in Band 6 tc at rows 473–474, cols 2269–2271) contain raw float32 -3.4028234663852886e+38 (-FLT_MAX) sentinels (evidence/prepared_manifest.json). Any spatial filter (scipy.ndimage.gaussian_filter), gradient operator, or linear/tree predictor applied before scrubbing val < -1e30 propagates -3.4e38 or NaN into active-footprint predictions.
  2. Mechanism B — Outside-Footprint NaN vs 0.0f (outside="zero"): In sample_submission.tif, the 7,111,787 pixels outside the 5,167,373-pixel rotated study footprint are NaN with nodata = None. If an upload validator evaluates np.all((arr >= 0.0) & (arr <= 1.0)) across the full 3730 x 3292 raster without masking np.isnan(arr), IEEE-754 returns False for NaN >= 0.0 and raises "Predicted values must be in range [0, 1]".
  3. How GEMSDOE75 Guarantees Immunity:
  4. scripts/prepare_data.py scrubs all 58,171 -3.4028235e+38 entries (val < -1e30) to NaN and median-imputes within the active footprint before any spatial filtering.
  5. vendor/gems57/submission_writer.py writes submissions/gemsdoe75-h75-strike-corrob-b2-d285-k38200-20261021-zero.tif with 0.0f outside the footprint and verifies on disk (scripts/verify_submission.py) that across all 12,279,160 cells (3730 x 3292): n_finite = 12,279,160, n_nan = 0, n_infinite = 0, min = 0.0, max = 1.0, emitted_positive_pixels = 38,200, on_catalogue_positive_pixels = 0, and d_le_2_count = 0.
